### Why stop local tuning at this checkpoint

The skill allows a stop after ten consecutive resolved gains of at most 0.5% or after an execution-path review finds no concrete, profile-supported experiment left in the current scope. Count only quality-screened full-systematics elapsed measurements against the current checkpoint. The copy trial contributes one resolved combined comparison at or below the threshold. The status-array candidate's bounded repeat reversed direction and exceeded the spread limit, leaving that earlier count unchanged. The recent stack comparison still improved the combined engineering endpoint by more than the threshold. The record does not establish a streak of ten. For the selected delivery, stop under the execution-path review criterion. The latest actionable local copy experiment resolved against adoption. The remaining dispatch, array, and tool owners include work required by the scientific prescription. The earlier native batch and neural-input trials did not establish a gain that survives this installed route. An event or container view needs a proof of which mutable decorations can be reread or borrowed. Sharing uncertainty inputs needs attributed repeated transforms, stable row ownership and preserved state validity order. Replacing owned NNJVT temporaries needs an allocation-lifetime trace and preservation of exact dense-layer operation order. Allocator and unattributed stack totals alone leave the removable work unproven. Nominal-only and stored controls address different endpoints, and changing the random stream has separate scientific acceptance. The startup profile does identify a concrete upstream loader design. The visible demo reads its selected CorrectionSet payload once into a string. One Python `plugins.prepare` call decodes that string before the native parser constructs the set. In the saved combined cProfile caller graph, 0.349 s of the 0.352 s cumulative time in 366 `json.loads` calls belonged to this one Python prepare call. Python prepare took 0.368 s in total. The single native `from_string` call took 0.870 s including native setup and provider construction. Both parsers consume the same payload text. The measurements establish duplicate parsing while the file is opened once for that load. Single-radius projection's byte-copy step is separate. The upstream design could use one parse with an explicit, sealed native-registration policy. The current general loader discovers Python descriptors and may run their configuration validation before it constructs native nodes. The installed demo explicitly loads its native library with discovery disabled, which narrows the possible fast path. A general skip would alter validation and error ordering. A trial needs an explicit registered-provider trust scope for checked artifacts, the ordinary loader for overrides and live discovery, and tests for malformed input, missing or duplicate registrations, descriptor rejection, precision, and existing error ordering.
